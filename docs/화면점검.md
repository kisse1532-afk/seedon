# 화면 점검표 — 디자인팀이 한 바퀴 돌면서 채운다

> **왜 이 파일이 있나 (2026.08.18)**
> 디자인팀은 지금까지 "오늘 뭘 볼까"를 매번 실장이 정해줬다. 그러니 어떤 화면은
> 여러 번 보고 어떤 화면은 한 번도 안 봤다. **화면 목록을 정해두고 한 바퀴 돈다.**
> 그리고 오늘부터 **화면 사진을 실제로 볼 수 있게 됐다**(`scripts/shot.mjs`).
> 그전까지는 코드만 읽고 추정했고, 그래서 카톡 로고 건에서 네 번 연속 틀렸다.

## 디자인팀의 목표 — 무엇이 "다 됐다"인가

**모든 화면이 아래 넷을 통과하는 것.** 한 바퀴 다 돌고 새 지적이 안 나오면 다 된 것이다.

1. **판정하는 느낌이 없다** — 자격 심사받는 관공서 화면처럼 보이지 않는다
2. **동정하는 톤이 없다** — 안쓰러워하는 색·문구가 없다
3. **어른용 서류처럼 안 보인다** / 반대로 **얕보는 느낌도 없다** (중고생은 애 취급을 제일 싫어한다)
4. **폰에서 안 깨진다** — 잘리는 글자, 가로 밀림, 두 줄 나는 전화번호가 없다

**2026-08-20에 일곱 칸을 한 바퀴 다 돌았다.** 카드가 많은 칸(어제)과 적은 칸(오늘)에서
각각 다른 문제가 나왔다 — 많으면 순서와 딱지 색, 적으면 여백과 안내문.
그리고 문화체험 칸에서 **절대규칙 위반 하나**를 찾았다(카드 설명 첫 문장에 대상 조건).

**2026-08-24에 로그인한 화면을 드디어 찍을 수 있게 됐다.** `scripts/shot-login.mjs`가
촬영용 계정으로 로그인해 찍는다(`--guest`를 붙이면 로그인 안 한 화면). 그동안 커뮤니티·
북마크·맞춤추천은 로그인해야 내용이 보이는데 한 번도 그 상태를 못 봐서, 제작 관점이
매번 "코드로만 본 추정"이라고 적을 수밖에 없었다.

```
NODE_USE_ENV_PROXY=1 node scripts/shot-login.mjs /community /bookmarks /recommend
NODE_USE_ENV_PROXY=1 node scripts/shot-login.mjs /mypage --guest
```

이 도구가 쓰는 계정(`seedon_shot`)은 **카드 성적표 집계에서 빠진다.**
다만 여기서 한 번 헛디뎠다 — 운영자 목록에 미리 넣어뒀는데, 그 표시는
**프로필이 만들어질 때** 붙는 거라 가입만 하고 프로필을 안 만든 이 계정에는
안 붙었다. 다른 장치(어느 주소에서 열렸나)가 우연히 막아주고 있었을 뿐이다.
같은 날 목록으로도 직접 거르게 고쳤다(`20260824_exclude_internal_by_email.sql`).
**로드 계정도 같은 구멍이 있었다** — 가입만 하고 프로필을 안 만들면 안 빠졌다.
`scripts/shot.mjs`(iframe 방식)는 화면이 덜 그려진 채로 찍히는 일이 있으니,
**로그인이 필요하거나 그리는 데 시간이 걸리는 화면은 이쪽을 쓴다.**

## 판단할 때 지킬 것

- **그림을 보고 말한 건 "확인", 코드만 보고 말한 건 "추정"으로 나눠 적는다**
- **폰(390px)을 먼저 본다.** 청소년은 폰으로 본다
- 필요한 화면 그림이 없으면 **요청한다.** 추측으로 메꾸지 않는다
- **없으면 "없음"으로 짧게 끝낸다.** 억지로 만들면 브리핑이 길어지고, 길면 로드가 안 읽는다

## 실장이 부르기 전에 할 일

```
NODE_USE_ENV_PROXY=1 npm run start &
node scripts/shot.mjs http://127.0.0.1:3000/ /category/housing /apply/edu-01 \
  --widths 390,1000 --out .shots
```
배포 주소는 못 찍는다(크롬이 이 환경 프록시를 못 씀). 로컬로 띄워 찍는다.
