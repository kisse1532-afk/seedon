## 0. 맥락 되찾기

세션은 매일 아무것도 모르는 상태로 시작한다. 일하기 전에 읽는다.

1. `docs/org_system.md` — 어떻게 일하는가
2. `CLAUDE.md` — 무엇을 만드는가. **절대규칙이 최상위**
3. `docs/team-context.md` — **로드가 이미 정한 것.** 정해진 걸 다시 묻지 않기 위해
4. 노션 MVP 현황 페이지 최근 2~3일치
5. `git log --oneline -20`

**어제 "확인 필요"로 남긴 것부터 처리하고 새 일을 시작한다.** 같은 것을 매일 새로 발견하고 매일 다시 미루는 게 제일 나쁘다.

## 1. 도구를 돌린다 (팀보다 먼저)

```
node scripts/team-brief.mjs       # ★ 팀이 읽을 "지금 상태" 생성
node scripts/org-sync.mjs         # ★ 기관 표 → 명부 · "이번 주에 볼 곳"
node scripts/cards-dump.mjs       # ★ 카드 전문 → docs/카드전문.md (CS·리서치가 읽는다)
node scripts/check-links.mjs
node scripts/check-programs.mjs
node scripts/verify-facts.mjs
```

앞의 셋을 **팀보다 먼저** 돌린다. 안 돌리면 팀이 어제 숫자로 판단하고 **이미 한 일을 "안 돼 있다"고 보고한다.**
`cards-dump.mjs`는 낙인 문구·행정용어·`~합니다`체가 걸린 카드 id도 같이 세어 준다. **판정은 CS팀이 한다.**

`--fix`를 붙이면 마감 지난 것은 자동 정리된다(`check-programs.mjs --fix`).

## 2. 헬스체크 + ⚠️ 자동 조임 확인

- **가입자 수를 반드시 확인한다.** `org_system.md` 1-3의 자동 조임 규칙이 여기서 걸린다

| 조건 | 조치 (로드 승인 불필요, 즉시 적용) |
|---|---|
| 가입자 **1명** 발생 | B 검증을 **당일**로 올린다 |
| 가입자 **10명** 돌파 | **전 팀 L1로 리셋** |
| 사고 1건 | 해당 팀만 1단계 강등 |

- seedon.vercel.app 렌더링 · Vercel 런타임 에러 · Supabase 로그
- **사이트 다운 등 심각한 문제면** 나머지 다 건너뛰고 복구 최우선, 즉시 알림

## 3. 팀 여섯을 전부 돌린다

**부를 때 자기 파일을 먼저 읽으라고 시킨다.** 팀은 쓰기 도구가 없으므로 **보고 → 실장이 근거를 직접 열어 확인 → 실장이 반영**한다.

| 팀 | 자기 파일 | 부르기 전에 실장이 할 일 |
|---|---|---|
| 리서치 | `기관명부` · `기관명부-기업재단` · `대학명부` · **`카드전문`** | 막혔다던 곳을 `fetch-pages.mjs`로 받아 경로를 넘긴다 |
| 디자인 | `화면점검` | `shot.mjs`로 화면을 찍어 경로를 넘긴다 (**폰 390 필수**) |
| 사업운영 | `약속점검` | 없음 |
| 전략기획실 | `기회달력` | 없음 |
| 마케팅 | `유입경로` | 없음 |
| CS | **`카드전문`** | 없음 (`cards-dump.mjs`가 이미 만들어 뒀다) |

**화면 찍는 법** — 배포 주소는 못 찍는다(크롬이 이 환경 프록시를 못 씀). 로컬로 띄워 찍는다.

```
NODE_USE_ENV_PROXY=1 npm run start &
node scripts/shot.mjs http://127.0.0.1:3000/ /category/housing /apply/edu-01 --widths 390,1000 --out .shots
```

**각 팀에서 반드시 받을 것** (`org_system.md` 1-5)

```
밖으로 나간 것 / 밖에서 배운 것
오늘 반영한 발전 1건  ← 개선인지 새 기능인지 표시
받은 인계 처리 여부
```

**"없음"이 며칠 이어지는 팀이 있으면 그건 팀 잘못이 아니라 일감이 안에만 있다는 뜻이다.** 실장이 바깥일을 줘야 한다.

## 4. 검증하고 반영한다

- **팀 보고를 그대로 옮기지 않는다.** 근거 URL을 직접 열어 확인한 뒤 반영한다
- **"막혔다"는 보고는 실장이 `fetch-pages.mjs`로 재확인한다. 예외 없이 전부.**
  팀 WebFetch가 503을 주는 곳의 **대부분이 curl로는 200이다** — 08.18 여섯 곳, 08.19 열세 곳 중 아홉 곳.
  재확인을 건너뛰면 팀이 살아있는 기관을 매일 버린다
- **인계를 중개하고 기록한다.** 팀끼리 직접 지시하지 않는다
- **사업운영팀의 수정 요구가 최우선이다.** 거짓말이 화면에 떠 있는 상태는 다른 모든 작업보다 급하다
- 반려한 건 **반려율**로 집계한다 (주간 보고에 들어간다)

## 5. 통합 브리핑 하나 — 아티팩트로

형식은 `docs/daily/_TEMPLATE.html`. **필수 5항목이 빠지면 브리핑 무효다.**

1. 팀별 산출물 (실물)
2. 실장 검증 결과 (통과/반려 + 사유)
3. 밖으로 나간 것 / 밖에서 배운 것
4. **오늘 반영한 발전 1건** (팀별)
5. 로드 결정 대기 목록 · 막힌 것

### ⚠️ 쓰는 말 — 절대규칙 3을 브리핑에도 적용한다

> 로드(2026.08.19): *"브리핑 스킬을 높여야 될 거 같아. 뭔 개소리인지 하나도 이해가 안 가."*
> 08.16에도 *"뭔말인지 모르겠어"*가 있었다. **두 번 났으면 그건 사고다.**

**중학생이 사전 없이 읽을 수 있어야 한다는 규칙은 카드에만 적용되는 게 아니다.**
낙인 문구 안 쓰는 회사를 만들면서 로드에게는 행정용어로 보고하면 같은 실패다.

| 쓰지 말 것 | 이렇게 |
|---|---|
| 함수명·파일명 (`fetchProgramsByCategory`, `queries.ts`) | 화면에서 무슨 일이 벌어지는지로 — "목록에 순서가 없었다" |
| 색 코드 (`#faf6ee`), 클래스명 | "딱지 색이 거의 같아서 구별이 안 됐다" |
| HTTP 503, curl, WebFetch, 프록시 | "우리 쪽에서만 안 열린다" |
| 절대규칙 1번, org_system 1-3, L2, 자동 조임 | 규칙 이름 대신 **내용**을 한 마디로 — "낙인 문구 금지" |
| 반려 / 제안 / 반영 / 산출물 / 인계 / 검증 | "팀이 이렇게 하자고 했는데 확인해보니 아니라서 안 했어요" |
| 마이그레이션, RLS, CASCADE, 외래키 | "계정을 지워도 이름이랑 전화번호가 남는 구조였다" |

**로드가 알고 싶은 것은 셋뿐이다.**

1. **오늘 화면에서 뭐가 달라졌나** — 코드가 아니라 청소년이 보는 것
2. **왜 그게 문제였나** — 청소년 입장에서 한 문장
3. **나는 뭘 하면 되나**

**"실장이 오늘 한 일"을 보고하지 마라. "씨드온이 오늘 어떻게 나아졌나"를 보고해라.**
이 둘은 다르다. 08.19에 전자를 썼다가 통째로 다시 썼다.

**전/후를 나란히 놓는다.** 말로 열 줄 설명하는 것보다 어제 문구와 오늘 문구를
붙여 놓는 게 빠르다. 틀에 `.ba`(before/after) 칸이 있다.

**쓰고 나서 한 번 읽어본다.** 로드가 이 문장에서 모를 단어가 하나라도 있으면 다시 쓴다.

**쓰는 법**

- **1번 결론은 팀 보고 요약이 아니라 실장 본인의 판단이다.** "팀이 이런 걸 올렸습니다"가 아니라 "제가 보기엔 지금 이쪽입니다"
- **"정할 것"에 심부름을 올리지 않는다.** 파일 받기·키 넣기는 "로드가 할 일"로 내린다. 정할 것은 방향이나 우선순위여야 한다
- **결정할 것은 하나로 좁힌다.** 셋을 나란히 놓으면 셋 다 안 정해진다
- **A4 한 장을 넘기지 않는다.** 길면 안 읽히고, 안 읽히면 지시가 안 나온다
- **올리기 전에 라이트·다크·폰 390px로 직접 찍어 확인한다** (`shot.mjs`)
- 대화창에도 같은 규칙을 쓴다. 브리핑은 쉽게 쓰고 대화창에서 전문용어로 되돌아가면 소용없다
- 대화창에는 결론과 정할 것만 짧게 쓰고 링크를 붙인다. `SendUserFile`은 쓰지 않는다

**끝나면** `docs/daily/YYYY-MM-DD.html`로 저장하고 커밋 · 노션에 날짜별 기록.

## 6. 토요일에는 주간 보고를 더한다

**로드가 3분 안에 훑고 "이건 빼"만 말할 수 있어야 한다.** 맨 위 네 줄이 전부다.

```
[이번 주 씨드온]
숫자   가입 N / 게시 N / 신청 N / 도움요청 N   (지난주 대비 ±)
새 것  N개   ← 뺄 거 있으면 말해줘
결정   로드가 정할 것 N개
```

그 아래: **새로 생긴 것**(각 한 줄 + 볼 수 있는 URL) / **고친 것**(개수 + 눈에 띄는 것 3개) / **뺀 것** / **되돌린 것**(많다고 문제 아님) / **밖으로**(보낸 것·온 회신) / **로드가 정할 것**(번호 매겨서) / **막힌 것**

**로드가 "이건 빼"라고 하면 다음 데일리에 즉시 제거한다. 이유를 묻지 않는다.**

## 트리거를 새 방으로 옮길 때

`create_trigger`를 **`persistent_session_id`도 `create_new_session_on_fire`도 주지 않고** 부르면 부른 방에 물린다. "커넥터가 저장되지 않았다" 경고는 **무시해도 된다** — 2026.08.17에 Supabase·GitHub·노션 셋 다 실제로 호출해 확인했다.

**`create_new_session_on_fire=true`로 만들지 말 것.** 그렇게 했을 때 커넥터가 안 실려 데일리가 통째로 못 돌았다.

**알림은 작업 중일 때 바로 안 뜬다.** 발사 기록만 남고 턴이 끝나야 도착한다. "발사됐는데 안 보인다"를 실패로 단정하지 말 것.
