# 씨드온 부서 에이전트 (5·6·7단계)

로드 결정(2026.08.16): "AI 직원 팀 빌딩 마스터 플랜" 5·6·7단계를 실제로 세운다.

## 왜 7단계를 먼저 세웠나

노션 기록(2026.08.13): *"8단계 원문의 7단계('마스터가 부서 보고를 검수') 구조가
빠져 있어서 자동화가 조용히 새고 있었다."*

부서부터 만들고 검수를 나중에 붙이면 그 상태를 6배로 만드는 것이다. 그래서
검수를 **약속이 아니라 구조**로 박았다.

## 구조

**부서는 조사하고, 실장(병준)이 확인하고, 실장이 반영한다.**

부서 에이전트에게는 **쓰기 도구를 주지 않는다.** `Write`·`Edit`·DB 도구가
없으므로, 부서가 스스로 프로그램을 올리거나 코드를 고치거나 노션을 쓰는 일이
구조적으로 불가능하다. "검수하겠다"는 다짐은 잊히지만 없는 권한은 잊히지 않는다.

```
부서 → (근거와 함께) 보고 → 실장이 직접 확인 → 실장이 반영 → 로드에게 보고
```

## 모든 부서가 지키는 것

1. **저장소 루트의 `CLAUDE.md`를 먼저 읽는다.** 절대규칙(낙인 문구 금지·쉬운 말·
   14세 이상)이 거기 있고 그게 최상위다.
2. **확인한 것과 추측을 반드시 구분해서 보고한다.** "아마", "일반적으로",
   "~로 보인다"는 추측이다. 그렇게 적고, 무엇을 못 봤는지도 적는다.
3. **근거 URL을 그대로 남긴다.** 요약만 주면 실장이 다시 찾아야 한다.
4. **못 한 건 못 했다고 한다.** 빈손 보고가 그럴듯한 거짓 보고보다 낫다.
5. **청소년 개인 사례를 만들어내지 않는다.** 예시가 필요하면 가상임을 명시한다.

## 비용 주의

부서를 부르면 그만큼 토큰을 쓴다. **필요할 때만 부른다** — 매일 전부 돌리지
않는다. 데일리는 지금처럼 실장이 직접 하고, 부서는 그 주제를 깊게 파야 할 때만
부른다.
