# 계정 삭제 요청이 오면 이렇게 한다

화면 두 곳(`lib/policy.ts`의 개인정보 안내, 마이페이지 아래)이 이렇게 약속하고 있다.

> 계정을 통째로 지우고 싶으면 아래 연락처로 알려주세요.
> 저장한 프로그램, 동의 기록, 남긴 후기까지 같이 지워드려요.

2026.08.18까지 이 요청이 오면 실행할 것이 아무것도 없었다. 사업운영팀이
찾아냈고 사실이었다. 지금은 아래 절차가 있다.

## 왜 계정만 지우면 안 되나

Supabase 대시보드에서 계정만 지우면 절반만 지워진다.

| 무엇 | 계정 삭제 시 | 약속에 포함? |
|---|---|---|
| 저장한 프로그램(북마크) | 같이 지워짐 | ✅ |
| 동의 기록(가입 정보) | 같이 지워짐 | ✅ |
| **남긴 후기** | **그대로 남음** (주인만 지워짐) | ❌ 약속 위반 |
| **관심 등록의 이름·연락처** | **그대로 남음** | ❌ 약속 위반 |
| 어느 카드가 몇 번 열렸나 | 남음 (누가 눌렀는지는 끊김) | 개인정보 아님 |

그래서 **먼저 이름·연락처·후기를 지우고, 그다음 계정을 지운다.** 순서를 바꾸면 안 된다.

## 순서

**1. 누구인지 찾는다**

Supabase → SQL Editor에서:

```sql
select id, email, created_at from auth.users where email = '요청한사람@메일주소';
```

나온 `id`가 아래에서 쓸 번호다.

**2. 이름·연락처·후기를 먼저 지운다**

```sql
select * from public.delete_account('여기에-1번에서-나온-id');
```

무엇을 몇 개 지웠는지 표로 나온다. `(대기)`라고 붙은 줄은 아직 안 지운 것이고,
3번에서 계정을 지우면 따라 지워질 개수다.

**3. 계정을 지운다**

Supabase → Authentication → Users → 해당 계정 → Delete user.

여기까지 하면 북마크와 동의 기록이 같이 지워진다.

**4. 확인하고 답장한다**

```sql
select count(*) from public.applications    where user_id = '그-id';
select count(*) from public.program_reviews where user_id = '그-id';
select count(*) from auth.users             where id      = '그-id';
```

셋 다 0이어야 한다. 그다음 요청한 사람에게 "다 지웠어요"라고 답한다.

## 도움 요청은 따로다 — 하지만 여기도 약속이 있다

`help_requests`(도움 요청 창구)에는 계정 번호가 없다. 로그인 없이도 남길 수
있는 창구라서 이름과 연락처만 들어 있다. 계정 삭제로는 안 지워진다.

**처음에 이걸 "화면이 약속한 범위 밖"이라고 적었는데 틀렸다**(사업운영팀이
2026.08.19에 지적). 도움 요청 폼 바로 아래(`HelpChatbot.tsx:269-273`)에 계정
삭제와는 **별개의 약속**이 이미 적혀 있다.

> 남겨주신 정보는 연락하는 데만 써요. 다 도와드리고 나서 1년이 지나면 지워요.
> 더 빨리 지우고 싶으면 (연락처)로 알려주세요.

즉 도움 요청은 계정과 무관하게 **그 자체로 "빨리 지워달라"를 받는 창구**다.
평소에는 처리가 끝나고 1년이 지나면 자동으로 지워지고
(`20260817_purge_finished_personal_data.sql`), 요청이 오면 아래처럼 바로 지운다.

```sql
-- 먼저 무엇이 지워질지 눈으로 본다
select id, program_id, name, contact, created_at from public.help_requests where contact = '연락처';
-- 확인한 뒤에 지운다
delete from public.help_requests where contact = '연락처';
```

## 며칠 안에 해야 하나 — 법으로 10일이다

개인정보 보호법 시행령 제43조③에 이렇게 적혀 있다. 2026.08.19에 법제처
국가법령정보센터(law.go.kr) 원문에서 직접 확인했다.

> 개인정보처리자는 ... 개인정보 정정·삭제 요구를 받은 날부터 **10일 이내에**
> ... 해당 개인정보의 정정·삭제 등의 조치를 한 경우에는 그 조치를 한 사실을
> ... 해당 정보주체에게 알려야 한다.

**요청을 받은 날부터 10일 안에 지우고, 지웠다고 알려줘야 한다.** 화면에는
"며칠 안에"라고 약속해두지 않았지만 법이 정한 기한이라 지켜야 한다.
지금은 요청이 0건이라 여유롭지만, 사람이 손으로 하는 절차라 요청이 여러 건
쌓이면 이 기한을 놓칠 수 있다. 그때가 버튼을 만들 때다.

## 아직 자동이 아니다

지금은 사람이 SQL을 치는 절차다. 가입자가 0명이라 이 정도로 충분하다.
요청이 잦아지면 관리자 화면에 버튼을 만든다. **먼저 만들지 않는다.**
