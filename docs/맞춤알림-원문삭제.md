# 공문 원본 30일 삭제 — 켜는 법 (아직 안 켰어요)

대표 결정(2026.11.29): 선생님·운영자가 올린 공문 원본은 **게시 후 30일** 보관한 뒤 지워요.
게시하지 않은 초안은 **올린 후 30일**이에요.

| 지우는 것 | 남기는 것 |
|---|---|
| 붙여넣은 원문 글, AI·사람이 만든 초안 사본, 올린 PDF | 게시된 카드, 누가·언제 올렸는지, 상태, 카드 연결, 지운 시각 |

하루 한 번 도는 작업이라 30일이 찬 뒤 최대 하루쯤 늦게 지워져요.

## 켜기 (대표 확인 후)

1. `20261128_custom_alerts.sql` 다음에 `20261129_notice_source_purge.sql`을 운영에 적용
2. Vercel 환경변수에 `CRON_SECRET`(아무도 못 맞힐 긴 글자)과 `SUPABASE_SERVICE_ROLE_KEY`
3. `vercel.json`의 `crons` 목록에 아래 한 줄을 넣는 PR을 만들어 머지

```json
{ "path": "/api/cron/purge-notices", "schedule": "30 18 * * *" }
```

`30 18 * * *`은 매일 한국 시간 새벽 3시 반쯤이에요.

**이 작업을 켜기 전에는 아무것도 지워지지 않아요.** 처리방침이 "30일 뒤 지워요"라고
말하므로, 공문 올리기를 실제로 쓰기 시작할 때 같이 켜야 해요.

작업이 500 응답을 주면 못 지운 것이 있다는 뜻이에요. 그 건은 다음 날 다시 시도해요.

Supabase 백업에는 백업 보관 기간 동안 남을 수 있어요.
