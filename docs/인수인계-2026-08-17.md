# 인수인계 — 2026.08.17 대화가 끝나는 시점

> **이 문서를 만든 이유**: 로드가 클라우드 환경의 네트워크 설정을 "전체"로 바꿨는데,
> 그건 **새 세션에만 적용된다.** 그래서 방을 옮겨야 하고, 옮기기 전에
> **대화에만 있던 것을 전부 여기 남긴다.** 이 문서가 있으면 이전 대화를 지워도 된다.
>
> 규칙은 `CLAUDE.md`가 최상위. 부서 배경은 `docs/team-context.md`.

## 1. 왜 방을 옮기나 — 네트워크 문제

**증상**: 부서 에이전트(리서치·마케팅 등)가 공식 페이지를 하나도 못 연다.
부서에게는 `WebFetch`뿐인데 그게 거의 모든 도메인에서 막힌다.

**진단 (2026.08.17 확인)**

| 방법 | k-startup·행안부 등 | 비고 |
|---|---|---|
| `WebFetch` (부서가 쓰는 것) | ❌ `EGRESS_BLOCKED` | |
| `curl` (실장이 쓰는 것) | ✅ 200 | 일부 도메인은 아래처럼 막힘 |

일부 도메인은 curl도 이렇게 막힌다:

```
Host not in allowlist: yesulsan.kr.
Add this host to your network egress settings to allow access.
```

**이 문구가 가리키는 곳이 클라우드 환경의 네트워크 설정이다.**

**로드가 한 조치 (2026.08.17)**
`claude.ai/code` → 입력창 위 구름 아이콘 → 환경 "한성재" 편집 →
**네트워크 액세스: 전체(Full)** 로 변경 완료.

**그런데 반영이 안 된 이유**: 그 화면에 *"환경 변경 사항은 새 세션에 적용됩니다"*
라고 적혀 있다. 설정을 바꾼 뒤 같은 대화에서 여러 번 재봤지만 계속 막혔다.
**그래서 새 세션(새 채팅)을 열어야 한다.**

**새 방에서 제일 먼저 할 일**: 아래 두 개를 재보고 결과를 로드에게 알린다.

```
curl -sS --max-time 15 "http://yesulsan.kr/notify/notice_view.jsp?nf_num=448" | head -1
```
그리고 `WebFetch`로 `https://www.mois.go.kr/frt/sub/a06/b02/digitalOpendataMydata/screen.do`

- 둘 다 열리면 → 해결. 부서가 스스로 검증할 수 있다
- 여전히 막히면 → 환경 설정이 원인이 아니라는 뜻이고, 다른 답을 찾아야 한다

## 2. 데일리 자동 실행을 옮겨야 한다

**지금 데일리 트리거는 이 대화 세션에 묶여 있다**(`persistent_session_id`).
방을 옮기면 자동 실행은 옛 방에 남는다.

**주의**: 예전에 "매 실행마다 새 세션"으로 바꿔봤더니
**커넥터(Supabase·GitHub·노션)가 안 실려서 데일리가 통째로 못 돌았다.**
그래서 되돌렸다. 자세한 경위는 `docs/daily-prompt.md` 맨 위.

**그러므로**: 새 방에서 데일리를 다시 걸 때는 **그 새 방에 묶는 방식**으로 건다.
새 세션 생성 방식으로 만들지 말 것.
